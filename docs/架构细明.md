2. 拆解

    class sence;
    主要成员变量    
    std::vector<std::shared_ptr<RenderObject>> m_transparentObjects;
    std::vector<std::shared_ptr<ProceduralEffect>> m_proceduralEffects;
    std::vector<std::shared_ptr<ParticleEmitter>> m_particleEmitters;
    std::shared_ptr<ICamera> m_activeCamera;

    用于存储以上成员变量
    类似与void addObject(std::shared_ptr<RenderObject> object);用于添加以上变量。

    main()函数中使用SceneBuilder来代理添加物体，创建材质和几何，材质走Assets::MaterialDesc+MaterialFactory::create(),MaterialFactory::create()其中调用类DefaultMaterialTemplate+MaterialInstance，底层调用krhi，对于模型材质来说，更加复杂需要更多参数来控制，使用MaterialSetDesc和SubmeshBinding 来进行封装，加载的时候用ModelFactory::load解包。模型就用modeLoder进行加载，然后底层调用assimp库和vkrhi。这只是用于添加renderobject()或者方便构建renderobject


    class renderpath；
    用于更加简便的创建rendergraph所需资源，通过获取全局单例RenderPathRegistry::instance()，然后注册管线，来声明pass和附件。标准管线注册时，会调用上下文的回调函数，具体在延迟渲染管线的默认管线函数里设置好了，后续这里需要配合渲染器协调与scene的关系，先不解释了。

    class renderer;
    基类构造函数：初始化全局setlayout和uniformbuffer；

    onResize() 调用renderpath->onResize（）;和子类 onAfterPathResize()

    renderFrame（）；调用子类buildSceneResources()场景资源构建，更新uniformbuffer和子类资源，更新世界时钟，调用renderpath基类render（）函数。

    子类构造函数，初始化默认和错误材质。

    onAfterPathResize()让renderpath重建资源m_renderPath->rebuildResources();。

    buildSceneResources(), 分析场景资源analysisScene();，然后如果要更新rendergrap重建rendergraph，否则重建资源。

    analysisScene()中 processObjects()遍历不透明物体，检查有没有实例化，获取submesh，继续遍历submesh，通过submesh的材质索引获取对应材质，验证材质是否有效，没有材质给默认材质，再验证材质模板是否有效，无限则用错误材质。buildMeshPSO（）生成pso，getOrAllocatePipelineIndex（），先在管线索引映射中，找一下有没有pso在result中对应的索引，没有就在result.pso中尾插，然后对应索引记录在pipelineIndexMap中。createMeshDrawItem（）通过pso对应的indx生成darwitem。obj->materials[submesh.materialIndex]->getRenderLayer()通过对应submesh的matIndex获取对应layer，最后返回AnalysisSceneResult result;


    doRebuildRenderGraph()中 m_renderPath->initialize();m_renderPath->rebuildResources(*m_analysisSceneResult);


    initialize()；如果rendergraph存在先把imugui资源清理，然后重置rendergraph。再重新创建rendergraph，先通过附件注册表获取附件，再创建附件id。实现子类方法buildConfigPasses（），将buildDefaultPipeline（）创建槽位的pass进行有序排列，将场景数据块填入pass中供粒子系统使用。pass->configure()执行对应pass定义的规则，下一步遍历所有对应的subpass，记录索引对应的passnode。
    基类 buildPresentationPasses（）这里做一个兜底的呈现pass，如果m_overlayPasses不为空，就做一个覆盖pass比如说ui。

    compileAndFinalize（）编译rendergraph，看看有没有呈现pass，如果有就执行preparePresentationExecutor()，继续执行onAfterCompile()和onAfterCompileImGui()。

    onAfterCompile（）遍历每个passnode，调用对应的onAfterCompile(ctx)

    onAfterCompileImGui（）对imgui进行初始化。

    rebuildResources（）执行子类doRebuildResources(sceneData)，先遍历所有材质，然后上传依赖的材质贴图和附件，然后遍历所有pass调用对应的onSceneData()，
    onSceneData（）先获取renderpass，然后清理掉drawitem，遍历之前场景分析的所有drawitem，找一下是否与当前layer和queue相同的drawitem，然后添加到executor中，再通过之前的pipelineindex找到对应的，pipelinehanldemapping再填入executor中提供上部renderpath调用，在DeferredRenderPath::buildConfigPasses（）调用pass->getSubpasses()，获得subpass，后续在compileAndFinalize（）编译rendergraph，进行排序pass，保证正确执行顺序

    render（） 执行m_renderGraph->execute（）根据是否为动态渲染调用对应passexecutors进行提交命令缓冲
