# StarryEngine 架构流程图

> 本文是 `docs/架构细明.md`（原始笔记）的**校正版流程图**。原件保留不改，
> 文中标注了「原件偏差」的位置；与代码不符处以代码为准。

---

## 0. 分层总览

```
apps/*/main.cpp                 ← 只做连接（<60 行）
  │
  ├─ src/app/                   L3 配置与诊断：AppConfig / RuntimeSettings / Diagnostics
  ├─ src/application/           L2 宿主：Application（窗口/循环/事件/设备丢失恢复）
  ├─ src/content/               L4 内容层（声明 + 定义 + 具体场景）
  │     render/                   RendererSwitcher（切渲染器+场景）、materials/
  │     renderpath/               StandardPipeline（声明）、RenderPathRegistry（定义）
  │     scene/                    SceneBuilder（基础件装配）
  │     scenes/pbr|raytrace/      具体内容
  │
  └─ src/renderer/, src/assets/, src/scene/, src/ui/, src/core/, src/event/, src/utils/, src/logging/
```

依赖方向单向：**L4(内容) → L2(宿主) → L1(渲染/资产/场景/UI) → L0(基础设施)**，
L1 不 include `app/` 与 `content/`。

## 1. 启动与装配（main 只做连接）

```
main()
 │
 ├─ 1. Logger::init()
 ├─ 2. AppConfig::load(argc, argv)
 ├─ 3. Application app(appCfg)
 │        ├─ Window (GLFW) 初始化
 │        ├─ VulkanRHI 初始化（Device/Queue/Swapchain/VMA）
 │        └─ 全局描述符池
 │
 ├─ 4. scene    = make_shared<Scene::Scene>()
 ├─ 5. renderer = make_shared<RasterRenderer>(rhi, pool, scene)     // 构造自包含：
 │        createGlobalSetLayout + createGlobalUniformBuffer + initDefaultMaterials
 ├─ 6. SceneBuilder(scene, res).addSkybox().addGrid().addCamera().build()
 │        res = SceneResources{ rhi, pool, renderer->getGlobalSetLayout(),
 │                              renderer->getGlobalDescriptorSet(0) }
 ├─ 7. (可选) ModelFactory::load(resMgr, pool, ModelDesc, MaterialSetDesc, mi)
 │        → mi.geometry / mi.parts / mi.outlineMaterial → scene->addObject()
 ├─ 8. renderPath = RenderPathRegistry::instance().create("deferred", rhi, w, h)
 ├─ 9. app.setRenderer(renderer, renderPath)   // 一步接线：renderer->setRenderPath
 │                                             //              + 记住 renderPath
 ├─10. app.setScene(scene)                     // 同步把 scene 交给 renderPath
 ├─11. app.initEventDispatcher()               // 相机控制在此绑定（相机必须已存在）
 └─12. app.run()
```

**原件偏差 ①**：原件写「通过 scene 创建 renderer」——实际是 `RasterRenderer` 持有 `scene` 引用，
方向是 renderer 依赖 scene；`renderer->setRenderPath()` 不是手动调用的，而是被
`Application::setRenderer(renderer, path)` 封装。

## 2. 每帧渲染

```
Application::run()
 └─ 每帧 Application::step()
      ├─ glfwPollEvents()
      ├─ tryBindCameraControl()                // 相机晚到时首帧补绑
      ├─ 等待帧内可用槽（in-flight）
      └─ rhi->renderFrame(lambda(encoder, imageIndex))
           └─ renderer->renderFrame(encoder, imageIndex, clock)
                ├─ buildSceneResources()          // 子类：材质纹理/实例缓冲
                ├─ updateGlobals(clock, slot)     // 全局 UBO：view/proj/lightVP/time
                ├─ renderPath->render(encoder, imageIndex)
                │    └─ RenderGraph::execute(...)
                │         └─ 逐 pass：executeDynamic(encoder, ...)
                │              └─ executor->execute(...)  // SceneDrawExecutor 等
                └─ submitFrameDataJobs(nextSlot)  // 帧间解耦(FID)：下帧数据提前准备
```

**原件偏差 ②**：原件说「准备上下文主要跑的是 renderer.renderFrame()」——正确；
但它跳过了 `path->render → RenderGraph::execute → pass executor` 这一层，
渲染命令实际是在 **executor** 里录制的。

## 3. 场景与创建层

### 3.1 Scene（数据容器）

```
class Scene
  m_allObjects / m_opaqueObjects / m_transparentObjects
  m_proceduralEffects / m_particleEmitters
  m_cameras / m_activeCamera
  addObject() → updateObjectClassification() + markContentDirty()   // 触发增量重分析
```

**原件偏差 ③**：原件漏了 `m_allObjects`、`m_opaqueObjects`、`m_cameras` 三个成员，
也漏了「addObject 自动分不透明/透明」这一步。

### 3.2 SceneBuilder（基础件装配，不创建任意材质）

```
SceneBuilder(scene, res)
  .addSkybox(hdrPath)   → IBLBuilder 烘 cubemap → BuiltinMaterials::createSkybox → ProceduralEffect
  .addGrid(size, div)   → GeometryGenerator::createGrid + BuiltinMaterials::createGrid → RenderObject
  .addObject(geo, mat, transform)   // 几何/材质由调用方提供
  .addCamera(CameraParams)          // 必须在 build() 前，否则相机控制绑定不到
  .build()
```

**原件偏差 ④**：原件说「SceneBuilder 负责创建材质和几何」——它只创建**基础件**（天空盒/网格）；
任意物体由调用方给 geometry + material；模型走 `ModelFactory`。

## 4. 材质与模型装配

### 4.1 普通材质

```
MaterialDesc (描述)  ──►  MaterialFactory::create(resMgr, pool, desc)
                             ├─ DefaultMaterialTemplate（shader 加载 + 布局合并 + variants）
                             ├─ MaterialInstance（描述符集 set0=全局, set≥1=材质私有）
                             └─ RHI（纹理/缓冲/采样器）
```

### 4.2 模型（资产与材质策略分离）

```
       ModelDesc（资产）                     MaterialSetDesc（材质策略）
    file / textureDir / skeleton        bindings(别名→MaterialDesc) / fallback shader /
    position / scale                    outline(描边 shader / scale / texture)
                └────────────┬───────────────────────┘
                             ▼
        ModelFactory::load(resMgr, pool, desc, set, out)
          ├─ loadModel()      ModelLoader → assimp → Geometry(Skeleton/Clip) → uploadToGPU
          └─ loadMaterials()  SubmeshBinding 匹配 → MaterialFactory::create
                              + 模板写(Outline,0) / 描边材质(Outline,1) / 骨骼绑定姿态
                             ▼
                    ModelInstance{ geometry, parts(子网格名→材质), outlineMaterial }
```

（`MaterialFactory` / `ModelFactory` 均在 `assets/loader/`；`assets/material/` 只放材质系统本体。）

**原件偏差 ⑤**：原件把 `MaterialSetDesc` / `SubmeshBinding` / `ModelFactory::load` 混在
`SceneBuilder` 段落里；实际这是**独立的模型装配链路**，与 SceneBuilder 无关。

---

## 5. 渲染路径：声明 → 定义 → 执行 → 建图

这是原件偏差最大的部分（原件把三层混成一层）。

```
① 声明（内容层，一次性，幂等）
   Content::StandardPipeline::declare(w, h)
       ├─ RenderLayers::setPass(层, 工厂)      // shadow/forward/surface(skybox+grid)/stencil/particles
       └─ RenderTextures::define(name, desc)   // SceneColor/Depth/Swapchain/ShadowMap

② 定义（按名创建路径）
   Content::RenderPathRegistry::create("deferred" | "raytrace" | 自定义)
       └─ 内部先调 StandardPipeline::declare(w,h)，再 new DeferredRenderPath(...)

③ 执行（引擎侧，把两张表变成 pass）
   DeferredRenderPath::buildDefaultPipeline()
       ├─ 同步 RenderTextures → m_textureDescs（本地表：交换链导入/resize 遍历要用）
       └─ RenderLayers::instance().build(ctx)   // 逐层调用工厂
              ctx = { width, height, setSlot(layer, pass) }   ← PassBuildContext（只剩这三项）
              工厂内部：make_shared<GraphicsPass>(...) → addSubpass(SubpassDesc{layer,queue}) → c.setSlot(layer, pass)

④ 建图 / 编译
   BaseRenderPath::initialize() → buildGraph()
       ├─ buildTextureIdMap()       m_textureDescs + RenderTextures → 纹理节点（Swapchain 走 import）
       ├─ buildConfigPasses()       GraphicsPass::configure()：按 (layer,queue) 命名 subpass + 连附件
       │                            未声明纹理/缺 layer/重复 key → LOG_ERROR 并跳过（不抛异常）
       ├─ buildPresentationPasses() 呈现链 / ImGui 叠加层（(UI,0)）
       └─ compileAndFinalize()      RenderGraph::compile → PipelineCache 建管线
```

**原件偏差 ⑥**：原件写「获取 RenderPathRegistry 单例后注册管线、声明 pass 和附件」——
现在 **pass/附件声明属于 `StandardPipeline`**，`RenderPathRegistry` 只负责「名字 → 路径工厂」。
`PassBuildContext` 已精简为 `width/height + setSlot`（`getGroupPass`、`texture/color/depth` 已删除）。

## 6. 分派：layer / queue 是唯一身份

约定：**layer = 一个 render pass，queue = 该 pass 内的 subpass 序号**。

```
材质                    DrawItem                        subpass（建图时声明）
setRenderLayer(N)  →  renderLayer / renderQueue   ←→   SubpassDesc{ layer=N, queue=Q }
setRenderQueue(Q)        │                                      │
                         ▼                                      ▼
              key = (layer<<32) | queue          m_keyToSubpass[key]（DeferredRenderPath 构建）
                         │                                      │
                         └──────────► GraphicsPass::onSceneData 按 key 匹配 subpass
                                             → executor->addDrawItem()
```

未声明层的材质/DrawItem 统一归入 `(Opaque, 0)`；key 找不到对应 subpass → 构建期 `LOG_ERROR`。

**原件偏差 ⑦**：原件没有这一层，而它是“材质 → pass/subpass”的唯一路由依据
（字符串 tag 已全部删除）。

## 7. 管线（PSO）选择与缓存

```
SceneAnalyzer            GraphicsPipelineState（顶点布局/拓扑/材质渲染状态/附件格式）
     └─ getOrAllocatePipelineIndex()  → DrawItem.pipelineIndex, sceneData.PSO[idx]
GraphicsPass::onSceneData
     └─ 对每个用到的 idx：PipelineCache::getOrCreateGraphicsPipeline(...)
            Key = { stateHash, renderPass, subpassIndex, colorFormat, depthFormat }
SceneDrawExecutor        bindPipeline(mapping[item->pipelineIndex]) → bindDescriptorSets → vkCmdDraw*
```

动态渲染下 `renderPass` 无效句柄、靠格式区分；resize 时可安全复用管线缓存
（旧 render pass 路径则必须失效）。

---

## 8. 描述符集与多帧

```
每个材质实例：set0 = 全局集（渲染器提供）   set≥1 = 材质私有（UBO/SSBO/贴图）
每个 set 按 in-flight 帧槽复制 N 份（RHI::kMaxFramesInFlight = 2）
   └─ solve 目的：CPU 录 N+1 帧时，GPU 可能还在用第 N 帧的绑定

注意三套索引空间不可混用：
  in-flight 帧槽   (0..kMaxFramesInFlight-1)   → 描述符集、全局 UBO
  swapchain 图像索引 (0..imageCount-1)          → attachment view、per-image semaphore
```

（曾经的 bug 就是这两者混用：`getAttachmentViewsForPass(passIdx, frameIndex)` 拿错 view。）

## 9. 扩展点一览

| 想做的事 | 接口 |
|---|---|
| 换某层的 pass 实现 | `RenderLayers::instance().setPass(layer, factory, /*overwrite=*/true)` |
| 新增自定义层 | `setUserLayer(8, "TestFx")` + `setPass(8, factory)` |
| 新增/覆盖附件 | `RenderTextures::instance().define(name, desc, /*overwrite=*/true)` |
| 新增自定义路径 | `RenderPathRegistry::instance().registerPath(name, factory, true)` |
| 材质层/队列 | `material->setRenderLayer(N); setRenderQueue(Q);` |
| 自定义绘制 | 实现 `IPassExecutor`，在 `<layer,queue>` 的 subpass 里 `setExecutor(...)` |

## 10. 与 `docs/架构细明.md` 的差异汇总

| 原件表述 | 校正 |
|---|---|
| 「通过 scene 创建 renderer」 | renderer 持有 scene 引用；装配由 `app.setRenderer(renderer, path)` 一次完成 |
| Scene 成员列 4 个 | 实际还有 `m_allObjects` / `m_opaqueObjects` / `m_cameras`；`addObject` 自动分类 |
| SceneBuilder 创建材质和几何 | 只建基础件（天空盒/网格）；任意物体由调用方给 geometry+material |
| 模型材质混在 SceneBuilder 段 | 独立链路：`ModelDesc` + `MaterialSetDesc` → `ModelFactory::load` |
| RenderPathRegistry 负责声明 pass/附件 | 声明在 `StandardPipeline`；registry 只做「名字→路径工厂→create」 |
| 未提分派机制 | `(layer, queue)` 是唯一身份，驱动 pass/subpass 路由与材质绑定 |
| 未提管线缓存/描述符集 | 见第 7、8 节（PSO key、每帧槽 N 份、两套索引空间） |
